# W2.3 — Selagem Gov.br

**Data:** 2026-10-07  
**Branch:** `audit/full-remediation-20261007`

## Finding confirmado

O callback podia chamar a selagem mesmo quando a troca do authorization code falhava. O handler aceitava `signingToken`, CPF, nome e nível como uma Server Function pública e marcava `gov_br_verified=true`; em falha, CPF/nome eram derivados do próprio envelope, não de uma identidade Gov.br validada.

## Correção

- `signContractWithGovBr` deixou de ser `createServerFn` e virou função server-only chamada exclusivamente pelo callback;
- o callback agora exige resposta OK do token endpoint, `access_token`, resposta OK do `userinfo` e `userinfo.sub` não vazio;
- se o envelope já possui CPF, o `sub` recebido precisa coincidir após normalização;
- falhas de provider, token, userinfo ou divergência redirecionam com erro explícito e não selam o envelope;
- o nível de confiabilidade é elevado para ouro somente quando a resposta de confiabilidade comprova essa informação.
