## 🛠️ Alterações Efetuadas

### 1. Banco de Dados (Supabase)
* **Arquivo:** [20260900000016_add_unread_count_to_conversations.sql](file:///c:/Users/Eduardo%20Ant%C3%B4nio%20Ramo/Music/travelagencias/supabase/migrations/20260900000016_add_unread_count_to_conversations.sql)

  * Criada a trigger function `handle_new_message_unread_count` e o trigger `on_message_inserted_unread_count` para incrementar automaticamente o contador de mensagens não lidas no banco de dados para mensagens de direção `'inbound'`.
  * Rodada query de migração de atualização para popular retroativamente o contador de mensagens não lidas de conversas existentes.
  * Migrações aplicadas no banco de dados com sucesso via `supabase db push`.

### 2. Inbox & Mensagens
* **Arquivos:** [useUnreadConversations.ts](file:///c:/Users/Eduardo%20Ant%C3%B4nio%20Ramo/Music/travelagencias/src/hooks/inbox/useUnreadConversations.ts) e [inbox.tsx](file:///c:/Users/Eduardo%20Ant%C3%B4nio%20Ramo/Music/travelagencias/src/routes/agency.$slug.inbox.tsx)
* **O que foi feito:**
  * **Fim do Polling redundante:** Removida a configuração `refetchInterval` da query do TanStack no hook `useUnreadConversations`.
  * **Otimização de mensagens na listagem:** A query lateral de listagem de conversas em `inbox.tsx` agora limita o select aninhado a apenas **1 única mensagem** (a mais recente), reduzindo o payload em ~95%.
  * **Atualização em tempo real:** A subscription de Realtime de mensagens no frontend agora invalida a query `"unread-conversations-count"` além da query `"conversations"`.
  * **Marcar como Lido:** Inserido um efeito de `useEffect` que, ao selecionar uma conversa, zera a coluna `unread_count` da conversa e marca todas as mensagens inbound como `'read'` no banco de dados.

### 3. Caching & Carga Única (HTTP)
* **Arquivos:** [__root.tsx](file:///c:/Users/Eduardo%20Ant%C3%B4nio%20Ramo/Music/travelagencias/src/routes/__root.tsx) e [auth.ts](file:///c:/Users/Eduardo%20Ant%C3%B4nio%20Ramo/Music/travelagencias/src/lib/auth.ts)
* **O que foi feito:**
  * **Cache de Platform Branding:** Introduzido um cache de promessa Singleton global `cachedBrandPromise` no `beforeLoad` do roteador principal para evitar que transições de abas/telas façam novas requisição HTTP de branding.
  * **Otimização do `useAuth`:** Adicionado um cache global e listeners unificados para o hook `useAuth()`. Apenas um componente fará o fetch inicial de `getSession()` na montagem da tela, eliminando as 14 requisições concorrentes a `/auth/v1/user`.

### 4. OCR de Proposta (Performance & Payload)
* **Arquivos:** [proposals.ts](file:///c:/Users/Eduardo%20Ant%C3%B4nio%20Ramo/Music/travelagencias/src/services/proposals.ts) e [index.ts (ai-orchestrator)](file:///c:/Users/Eduardo%20Ant%C3%B4nio%20Ramo/Music/travelagencias/supabase/functions/ai-orchestrator/index.ts)
* **O que foi feito:**
  * **Upload Prévio via Storage:** O frontend agora tenta fazer upload do PDF de proposta para a pasta temporária `ocr_temp` no bucket `proposals_exports_bucket` e passa apenas o link de referência (`file_path`) para a Edge Function. Mantém fallback automático para envio original base64 se houver alguma falha de RLS no Storage.
  * **Autolimpeza e Processamento Interno:** A Edge Function baixa o arquivo internamente do Storage de forma ágil, processa o OCR e, através de um bloco `finally`, apaga o arquivo temporário do bucket para mantê-lo limpo.
  * **CORS Preflight Cache:** Adicionado `"Access-Control-Max-Age": "86400"` nos cabeçalhos OPTIONS da Edge Function, cacheando o preflight por 24 horas no navegador.

### 5. Escalabilidade & Paginação
* **Arquivos:** [crm.ts](file:///c:/Users/Eduardo%20Ant%C3%B4nio%20Ramo/Music/travelagencias/src/services/crm.ts) e [proposals.ts](file:///c:/Users/Eduardo%20Ant%C3%B4nio%20Ramo/Music/travelagencias/src/services/proposals.ts)
* **O que foi feito:**
  * **Limite do Kanban:** Adicionado um limite de 300 leads no Kanban de CRM ativo, ordenados por atualizações mais recentes (`updated_at desc`), prevenindo travamento por volume.
  * **Limite de Dropdowns:** Otimizadas as funções `fetchClientsPick` e `fetchLeadsPick` para carregar 200 itens por padrão e aceitar busca dinâmica server-side de 50 itens via `.ilike(...)`, reduzindo o payload de dropdowns de 5000 itens para menos de 100 itens de forma dinâmica.
