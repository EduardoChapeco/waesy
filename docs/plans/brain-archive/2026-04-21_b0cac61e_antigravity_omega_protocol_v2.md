## Seção 1 — Filosofia e Fundamentos do Amplificador

### O Problema Real

Um LLM padrão, sem framework de amplificação, comporta-se como um estudante
respondendo uma prova: vai direto à primeira resposta plausível que encontra.
Não planeja. Não questiona. Não valida. Não conecta com contexto anterior.

O que separa o Claude Opus 4.6 de modelos menores não é apenas capacidade bruta
— é a profundidade de raciocínio que ele aplica naturalmente. O ANTIGRAVITY OMEGA
**injeta essa profundidade artificialmente** em qualquer LLM através de estrutura
de pensamento obrigatória.

O que torna o Lovable, Manus, e Devin tão eficazes: seus system prompts não apenas
descrevem o que o modelo deve fazer — eles **fragmentam e sequenciam** o processamento
de forma que o modelo não pode pular etapas críticas. Isso é o Bootstrap Pipeline.

### Os 3 Princípios Fundamentais

```
PRINCÍPIO 1 — ESTRUTURA ANTES DE RESPOSTA
  Nenhum output é gerado sem um plano de raciocínio explícito.
  O modelo que planeja produz 40-60% menos erros que o modelo que improvisa.

PRINCÍPIO 2 — EVIDÊNCIA ANTES DE CONCLUSÃO
  Toda afirmação deriva de observação verificável no código/sistema.
  Inferências são marcadas como tal e distinguidas de fatos observados.

PRINCÍPIO 3 — AUTOCRÍTICA ANTES DE ENTREGA
  O output passa por um loop de revisão interna antes de chegar ao usuário.
  O modelo que revisa o próprio output encontra 30-50% mais problemas.
```

## Seção 2 — Chain-of-Thought Obrigatório (CoT OMEGA)

### Diferença entre CoT Básico e CoT OMEGA

```
CoT BÁSICO (ineficaz):
"Pense passo a passo antes de responder."
→ O modelo improvisa os passos. Pula etapas. Chega à mesma conclusão rápida.

CoT OMEGA (estruturado e obrigatório):
Os passos são DEFINIDOS, SEQUENCIADOS e GATE-CONTROLLED.
O modelo NÃO pode passar para o próximo passo sem completar o anterior.
Cada passo tem critério de conclusão explícito.
```

### Template CoT OMEGA — Injection no System Prompt

```xml
<cognitive_protocol mandatory="true" version="omega">

  <phase id="1" name="DECOMPOSITION" gate="must_complete_before_next">
    <instruction>
      Antes de qualquer análise ou código:
      1. Liste TODOS os sub-problemas contidos no pedido atual
      2. Para cada sub-problema, identifique:
         - Tipo: [arquitetura | segurança | performance | lógica | dados | UX]
         - Dependências: quais outros sub-problemas precisam ser resolvidos primeiro
         - Critério de sucesso: como você saberá que este sub-problema foi resolvido
      3. Ordene os sub-problemas por prioridade e dependência
      GATE: Não prossiga sem ter pelo menos 3 sub-problemas identificados (ou 1 se o
      pedido for genuinamente simples — declare explicitamente se for o caso)
    </instruction>
  </phase>

  <phase id="2" name="EVIDENCE_GATHERING" gate="must_complete_before_next">
    <instruction>
      Para cada sub-problema identificado:
      1. Cite o CÓDIGO EXATO ou COMPORTAMENTO EXATO que é evidência do problema
         Formato: [arquivo:linha] `código literal`
      2. Separe explicitamente:
         a) FATOS OBSERVADOS: o que está no código como está
         b) INFERÊNCIAS FUNDAMENTADAS: conclusões lógicas dos fatos + justificativa
         c) HIPÓTESES: suposições que precisam de verificação adicional
      GATE: Não existe problema sem evidência. Se não encontrou evidência,
      declare "evidência insuficiente" e especifique o que precisaria ver.
    </instruction>
  </phase>

  <phase id="3" name="CAUSAL_CHAIN_ANALYSIS" gate="must_complete_before_next">
    <instruction>
      Para cada problema confirmado com evidência:
      Trace a cadeia causal completa usando o formato:
        ROOT_CAUSE → TRIGGERING_CONDITION → MECHANISM → MANIFESTATION → BUSINESS_IMPACT
      Exemplo real:
        Falta de índice em user_id → Query executada em scan full table →
        PostgreSQL faz seq scan em 500k rows → Timeout em 30s →
        Usuário vê "Erro ao carregar reservas" em horário de pico
      GATE: Se você não consegue completar a cadeia até BUSINESS_IMPACT,
      o problema ainda não foi entendido. Continue investigando.
    </instruction>
  </phase>

  <phase id="4" name="SOLUTION_SPACE" gate="must_complete_before_next">
    <instruction>
      Para cada problema crítico (severidade ALTA ou CRÍTICA):
      Gere EXATAMENTE 3 soluções possíveis, avaliadas em:
        - Eficácia: resolve 100% do problema? (sim/não/parcial)
        - Complexidade: horas de implementação estimadas
        - Risco de regressão: baixo/médio/alto + justificativa
        - Alinhamento com arquitetura atual: conflita? complementa?
      Selecione a solução ótima com justificativa explícita.
      GATE: A solução selecionada deve ter implementação completa,
      não esboço. Se não puder implementar completamente agora, diga por quê.
    </instruction>
  </phase>

  <phase id="5" name="ADVERSARIAL_VALIDATION" gate="must_complete_before_next">
    <instruction>
      Teste sua solução contra os seguintes adversários:
        ADVERSÁRIO 1 — Edge Cases: O que acontece com entrada vazia, nula, zero,
          string vazia, array vazio, data inválida, user sem permissão?
        ADVERSÁRIO 2 — Failure Modes: O que acontece se uma dependência falha
          parcialmente? Se o banco está lento? Se o serviço externo retorna 500?
        ADVERSÁRIO 3 — Concorrência: O que acontece com 100 requisições simultâneas?
          Há race conditions? Deadlocks possíveis?
        ADVERSÁRIO 4 — Malicious Input: Um usuário malicioso pode explorar esta solução?
      Se a solução falha em qualquer adversário, corrija antes de prosseguir.
    </instruction>
  </phase>

  <phase id="6" name="OUTPUT_FORMATION" gate="final">
    <instruction>
      Apenas após completar todas as fases anteriores:
      Forme o output usando o MASTER PROMPT TEMPLATE (Seção 28).
      O output deve conter APENAS conclusões suportadas pelas fases anteriores.
      Declare explicitamente qualquer lacuna de evidência ou incerteza.
    </instruction>
  </phase>

</cognitive_protocol>
```

## Seção 3 — Tree-of-Thought (ToT) para Decisões Críticas

### Quando Ativar ToT

ToT é computacionalmente mais caro que CoT. Use obrigatoriamente quando:
- Há múltiplas arquiteturas possíveis e a escolha errada causa refatoração massiva
- O diagnóstico de um problema tem mais de uma causa raiz plausível
- A solução de segurança envolve trade-off entre segurança e usabilidade
- Uma decisão de schema de banco é irreversível

### Template ToT OMEGA

```
═══════════════════════════════════════════════════════
TREE-OF-THOUGHT ANALYSIS — [NOME DO PROBLEMA]
Ativado por: [agente] | Tipo: [arquitetura|diagnóstico|segurança|schema]
═══════════════════════════════════════════════════════

NIVEL 0 — PROBLEMA ROOT
  [Descrição precisa do problema a ser decidido]
  Critério de decisão: [como saberemos qual caminho é melhor]

NIVEL 1 — HIPÓTESES RAIZ (gerar 3-5, podar para top 2-3)
│
├── [H1] [Nome da hipótese/abordagem]
│     Premissa central: [...]
│     Evidências que suportam: [cite código/dados]
│     Evidências que contradizem: [cite código/dados]
│     Viabilidade técnica: [0-10] | Justificativa: [...]
│     Alinhamento com arquitetura atual: [alto/médio/baixo]
│     → SCORE COMPOSTO: [média ponderada]
│
├── [H2] [Nome da hipótese/abordagem]
│     Premissa central: [...]
│     Evidências que suportam: [...]
│     Evidências que contradizem: [...]
│     Viabilidade técnica: [0-10]
│     Alinhamento com arquitetura atual: [alto/médio/baixo]
│     → SCORE COMPOSTO: [...]
│
└── [H3] [Nome da hipótese/abordagem] (se aplicável)
      [mesma estrutura]

PODA NIVEL 1: Eliminar hipóteses com score < 6.0
Hipóteses que avançam: [H1, H2] / [H1] / [H1, H3]

NIVEL 2 — EXPLORAÇÃO PROFUNDA (apenas hipóteses sobreviventes)
│
├── [H1] — Aprofundamento
│     Sub-caminho A: [implementação/abordagem específica]
│       Vantagens concretas: [lista]
│       Desvantagens concretas: [lista]
│       Prova de conceito: [código ou pseudocódigo real]
│       → Viabilidade A: [0-10]
│     Sub-caminho B: [implementação/abordagem alternativa]
│       [mesma estrutura]
│       → Viabilidade B: [0-10]
│     MELHOR SUB-CAMINHO: [A ou B] | Score: [0-10]
│
└── [H2] — Aprofundamento
      [mesma estrutura]

NIVEL 3 — CONVERGÊNCIA FINAL
  Caminho vencedor: [H? Sub-caminho ?]
  Score final: [0-10]
  
  JUSTIFICATIVA COMPLETA:
  [Por que este caminho supera os outros, citando evidências específicas]
  
  RISCOS RESIDUAIS:
  [O que pode ainda dar errado com esta escolha e como mitigar]
  
  DECISÃO: [Declaração clara e implementável da escolha feita]
═══════════════════════════════════════════════════════
```

## Seção 4 — Self-Consistency Sampling

```xml
<self_consistency_protocol>
  INSTRUÇÃO OBRIGATÓRIA: Após formular qualquer conclusão crítica, execute:

  PASS 1 — PERSPECTIVA ALTERNATIVA
    Reaborde o mesmo problema de um ângulo completamente diferente.
    Se analisou estrutura → agora analise comportamento em runtime.
    Se analisou código → agora analise dados que o código processa.
    Se analisou caminho feliz → agora analise caminhos de falha.
    
    Resultado da perspectiva alternativa: [...]
    Converge com a conclusão original? [SIM/NÃO/PARCIALMENTE]

  PASS 2 — DEVIL'S ADVOCATE
    Assuma que sua conclusão principal está ERRADA.
    Pergunta: "Que evidência existiria no código/sistema se eu estivesse errado?"
    Busque ativamente essa evidência.
    
    Evidência buscada: [...]
    Encontrada? [SIM → revisar conclusão / NÃO → confiança aumentada]

  PASS 3 — CALIBRAÇÃO FINAL
    CONVERGE + SEM_EVIDÊNCIA_CONTRÁRIA → Alta confiança (declara 85-95%)
    CONVERGE + EVIDÊNCIA_PARCIAL_CONTRÁRIA → Confiança média (declara 60-80%)
    DIVERGE → PARE. Identifique a fonte da divergência antes de concluir.
    
    Nível de confiança declarado: [X%]
    Raciocínio para este nível: [...]
</self_consistency_protocol>
```

║         técnico exato. Proibido: 'em algum lugar', 'talvez',          ║

## Seção 6 — Auto-Critique Loop

```xml
<auto_critique_mandatory version="omega">
  EXECUÇÃO OBRIGATÓRIA antes de qualquer output final.
  Falha em qualquer checkpoint = revisão obrigatória.

  ┌─ CHECKPOINT 1: COMPLETENESS ─────────────────────────────────────┐
  │  □ Respondi todos os aspectos explícitos do pedido?               │
  │  □ Respondi os aspectos implícitos (o que o usuário precisa       │
  │    mas não pediu explicitamente)?                                  │
  │  □ Há alguma dimensão do problema que ignorei completamente?       │
  │  □ Há stakeholders afetados que não considerei?                   │
  └───────────────────────────────────────────────────────────────────┘

  ┌─ CHECKPOINT 2: QUALITY ───────────────────────────────────────────┐
  │  □ Cada problema listado tem: localização + causa + solução +      │
  │    impacto de negócio?                                             │
  │  □ Cada solução é implementável sem informação adicional?          │
  │  □ O código fornecido compila/executa como está?                  │
  │  □ Os níveis de severidade refletem impacto real de produção?      │
  └───────────────────────────────────────────────────────────────────┘

  ┌─ CHECKPOINT 3: CONSTITUTIONAL ───────────────────────────────────┐
  │  Verificar M01 a M12 (Seção 5).                                   │
  │  Para cada violação encontrada: CORRIGIR antes de continuar.      │
  └───────────────────────────────────────────────────────────────────┘

  ┌─ CHECKPOINT 4: CALIBRATION ──────────────────────────────────────┐
  │  □ Estou sendo específico o o suficiente (ou estou sendo vago)?     │
  │  □ Estou sendo honesto sobre o que não sei?                       │
  │  □ Estou subestimando ou superestimando a severidade?             │
  │  □ Meu confidence score é calibrado para a evidência que tenho?   │
  └───────────────────────────────────────────────────────────────────┘

  TODOS OS CHECKPOINTS PASSADOS → Gerar output final
  QUALQUER CHECKPOINT FALHADO → Revisar e repetir
</auto_critique_mandatory>
```

## Seção 7 — Bootstrap de Etapas (Estilo Lovable/Manus/Devin)

O segredo dos melhores sistemas de IA não é apenas o que dizem — é como
**fragmentam e sequenciam** o processamento em fases com gates obrigatórios.

```
╔══════════════════════════════════════════════════════════════════════╗
║              ANTIGRAVITY BOOTSTRAP PIPELINE — 7 FASES                ║
╠══════════════════════════════════════════════════════════════════════╣
║                                                                      ║
║  FASE 0 — INTENT PARSING                                             ║
║  ─────────────────────────────────────────────────────────────────  ║
║  Input bruto → Extração de intenção em 3 camadas:                   ║
║                                                                      ║
║  [PEDIDO EXPLÍCITO]  O que foi literalmente solicitado               ║
║  [PEDIDO IMPLÍCITO]  O que está subentendido pelo contexto           ║
║  [PEDIDO LATENTE]    O que o usuário vai querer após ver o output    ║
║                                                                      ║
║  Ação: Responder todos os três. Não apenas o explícito.              ║
║                                                                      ║
║  FASE 1 — CONTEXT LOADING                                            ║
║  ─────────────────────────────────────────────────────────────────  ║
║  Carregar da Camada de Memória (Parte II):                           ║
║    → Decisões arquiteturais já tomadas para este projeto             ║
║    → Problemas já identificados neste módulo                         ║
║    → Padrões de código aprovados                                     ║
║    → Preferências e convenções do projeto                            ║
║  Ação: Injetar no contexto antes da análise para não contradizer     ║
║  decisões anteriores sem justificativa explícita.                    ║
║                                                                      ║
║  FASE 2 — SCOPE DEFINITION                                           ║
║  ─────────────────────────────────────────────────────────────────  ║
║  Definir e comunicar ao usuário:                                     ║

## Seção 9 — Mem0: Memória Semântica + Grafo (Camada 3)

Mem0 (Apache 2.0, 37k+ stars GitHub) é a mais avançada camada de memória
semântica open-source. +26% precisão vs. OpenAI Memory, 91% menos latência
que abordagem full-context, 90% redução de tokens.

```python
# ANTIGRAVITY OMEGA — Mem0 Semantic Memory Layer
# Arquivo: /antigravity/memory/semantic_memory.py
# Dependências: pip install mem0ai qdrant-client

from mem0 import Memory
from typing import Optional, List, Dict, Any
from dataclasses import dataclass
from enum import Enum

class MemoryType(Enum):
    ARCHITECTURAL_DECISION = "architectural_decision"
    CODE_PATTERN = "code_pattern"
    KNOWN_ISSUE = "known_issue"
    USER_PREFERENCE = "user_preference"
    MODULE_CONTEXT = "module_context"
    AGENT_FINDING = "agent_finding"

@dataclass
class AntigravityMemory:
    content: str
    type: MemoryType
    agent: str
    severity: Optional[str] = None
    status: Optional[str] = None
    module: Optional[str] = None
    metadata: Optional[Dict] = None

class AntigravitySemanticMemory:
    """
    Camada de memória semântica para o ANTIGRAVITY OMEGA.
    Gerencia conhecimento persistente sobre o projeto através de
    armazenamento vetorial + grafo de entidades + key-value store.
    """

    def __init__(self, project_id: str, config: Optional[Dict] = None):
        self.project_id = project_id
        self.config = config or self._default_config()
        self.memory = Memory.from_config(self.config)

    def _default_config(self) -> Dict:
        return {
            "vector_store": {
                "provider": "qdrant",
                "config": {
                    "collection_name": f"antigravity_{self.project_id}",
                    "host": "localhost",
                    "port": 6333,
                    "embedding_model_dims": 1536
                }
            },
            "graph_store": {
                "provider": "neo4j",
                "config": {
                    "url": "bolt://localhost:7687",
                    "username": "neo4j",
                    "password": "antigravity_password"
                }
            },
            "llm": {
                "provider": "anthropic",
                "config": {
                    "model": "claude-sonnet-4-6",
                    "temperature": 0.1,
                    "max_tokens": 2000
                }
            },
            "embedder": {
                "provider": "openai",
                "config": {"model": "text-embedding-3-small"}
            },
            "version": "v1.1"
        }

    def store(self, memory: AntigravityMemory) -> str:
        """Armazena qualquer tipo de memória no sistema semântico."""
        metadata = {
            "type": memory.type.value,
            "agent": memory.agent,
            "project_id": self.project_id,
            **(memory.metadata or {})
        }
        if memory.severity:
            metadata["severity"] = memory.severity
        if memory.status:
            metadata["status"] = memory.status
        if memory.module:
            metadata["module"] = memory.module

        messages = [{"role": "user", "content": memory.content}]
        result = self.memory.add(messages, user_id=self.project_id, metadata=metadata)
        return result.get("id", "")

    def store_architectural_decision(
        self, decision: str, rationale: str, agent: str,
        affected_modules: List[str]
    ) -> str:
        content = (
            f"DECISÃO ARQUITETURAL: {decision}\n"
            f"JUSTIFICATIVA: {rationale}\n"
            f"MÓDULOS AFETADOS: {', '.join(affected_modules)}\n"
            f"AGENTE: {agent}"
        )
        return self.store(AntigravityMemory(
            content=content,
            type=MemoryType.ARCHITECTURAL_DECISION,
            agent=agent,
            module=', '.join(affected_modules),
            metadata={"affected_modules": affected_modules}
        ))

    def store_known_issue(
        self, module: str, issue: str, severity: str,
        status: str, agent: str, resolution: Optional[str] = None
    ) -> str:
        content = (
            f"PROBLEMA CONHECIDO [{severity.upper()}] em {module}:\n"
            f"{issue}"
            + (f"\nRESOLUÇÃO: {resolution}" if resolution else "")
        )
        return self.store(AntigravityMemory(
            content=content,
            type=MemoryType.KNOWN_ISSUE,
            agent=agent,
            severity=severity,
            status=status,
            module=module
        ))

    def retrieve_for_agent(
        self, agent_name: str, current_task: str, limit: int = 15
    ) -> str:
        """
        Recupera contexto relevante e formata para injeção no system prompt.
        Este método é chamado automaticamente pelo Bootstrap Pipeline Fase 1.
        """
        results = self.memory.search(
            query=f"[{agent_name}] {current_task}",
            user_id=self.project_id,
            limit=limit
        )
        memories = results.get("results", [])
        if not memories:
            return ""

        sections: Dict[str, List[str]] = {
            "architectural_decision": [],
            "known_issue": [],
            "code_pattern": [],
            "user_preference": [],
        }
        for m in memories:
            mtype = m.get("metadata", {}).get("type", "other")
            if mtype in sections:
                sections[mtype].append(m["memory"])

        lines = ["\n## CONTEXTO DE MEMÓRIA DO PROJETO (Auto-carregado)\n"]
        if sections["architectural_decision"]:
            lines.append("### Decisões Arquiteturais Vigentes:")
            lines += [f"  → {d}" for d in sections["architectural_decision"]]
        if sections["known_issue"]:
            lines.append("\n### Problemas Conhecidos (não re-diagnosticar):")
            lines += [f"  ⚠ {i}" for i in sections["known_issue"]]
        if sections["code_pattern"]:
            lines.append("\n### Padrões de Código Aprovados:")
            lines += [f"  ✓ {p}" for p in sections["code_pattern"]]
        if sections["user_preference"]:
            lines.append("\n### Preferências do Projeto:")
            lines += [f"  ● {p}" for p in sections["user_preference"]]

        return "\n".join(lines)
```

## Seção 10 — Letta/MemGPT: Memória Episódica OS-Inspired (Camada 2)

Letta (ex-MemGPT, open-source) é o framework que trata o LLM como um sistema
operacional: o agente gerencia seu próprio context window, decidindo o que manter
em "RAM" (Core Memory) e o que mover para "disco" (Archival/Recall Storage).

```typescript
// ANTIGRAVITY OMEGA — Letta Episodic Memory Layer
// Arquivo: /antigravity/memory/episodic_memory.ts
// Dependências: npm install letta-client

import { Letta, CreateBlock } from 'letta-client';

interface AgentSession {
  agentId: string;
  agentName: string;
  projectId: string;
}

export class AntigravityEpisodicMemory {
  private client: Letta;
  private sessions = new Map<string, AgentSession>();

  constructor(baseUrl = 'http://localhost:8283') {
    this.client = new Letta({ baseUrl });
  }

  /**
   * Inicializa (ou recupera) um agente com memória persistente.
   * Agentes são identificados por nome + projectId — mesma identidade
   * persiste entre sessões.
   */
  async getOrCreateAgent(
    agentName: string,
    agentPersona: string,
    projectId: string
  ): Promise<string> {
    const key = `${agentName}_${projectId}`;
    if (this.sessions.has(key)) {
      return this.sessions.get(key)!.agentId;
    }

    // Buscar agente existente
    const agents = await this.client.agents.list();
    const existing = agents.find(
      (a: any) => a.name === `antigravity_${key}`
    );
    if (existing) {
      this.sessions.set(key, { agentId: existing.id, agentName, projectId });
      return existing.id;
    }

    // Criar novo agente com memória estruturada
    const agentState = await this.client.agents.create({
      name: `antigravity_${key}`,
      model: 'anthropic/claude-sonnet-4-6',
      embedding: 'openai/text-embedding-3-small',
      memory_blocks: [
        CreateBlock({
          label: 'persona',
          value: agentPersona,
          limit: 2000,
        }),
        CreateBlock({
          label: 'project_context',
          value: `Projeto: ${projectId}\nStatus: Inicializado\nÚltima análise: Nenhuma`,
          limit: 3000,
        }),
        CreateBlock({
          label: 'active_issues',
          value: 'Nenhum problema ativo registrado ainda.',
          limit: 4000,
        }),
        CreateBlock({
          label: 'decisions_log',
          value: 'Nenhuma decisão registrada ainda.',
          limit: 4000,
        }),
      ],
      system: this.buildAgentSystemPrompt(agentName, projectId),
    });

    const agentId = agentState.id;
    this.sessions.set(key, { agentId, agentName, projectId });
    return agentId;
  }

  /**
   * Envia uma mensagem ao agente com contexto persistente.
   * O agente automaticamente atualiza sua Core Memory com novos aprendizados.
   */
  async sendMessage(
    agentId: string,
    message: string
  ): Promise<{ response: string; memoryUpdated: boolean }> {
    const result = await this.client.agents.messages.create(agentId, {
      messages: [{ role: 'user', content: message }],
    });

    const textContent = result.messages
      .filter((m: any) => m.message_type === 'assistant_message')
      .map((m: any) => m.content)
      .join('\n');

    const memoryUpdated = result.messages.some(
      (m: any) => m.message_type === 'tool_call' &&
        (m.tool_call?.name?.includes('core_memory') ||
         m.tool_call?.name?.includes('archival_memory'))
    );

    return { response: textContent, memoryUpdated };
  }

  /**
   * Recupera o histórico de sessões anteriores para um agente.
   * Usado pelo Bootstrap Pipeline para carregar contexto cross-session.
   */
  async getSessionHistory(
    agentId: string, limit = 20
  ): Promise<string> {
    const messages = await this.client.agents.messages.list(agentId, {
      limit,
    });

    return messages
      .filter((m: any) => m.message_type !== 'system_message')
      .map((m: any) => `[${m.role?.toUpperCase() || 'MSG'}]: ${m.content}`)
      .join('\n');
  }

  private buildAgentSystemPrompt(agentName: string, projectId: string): string {
    return `Você é o agente ${agentName} do sistema ANTIGRAVITY OMEGA,
operando para o projeto ${projectId}.

INSTRUÇÕES DE MEMÓRIA:
- Use core_memory_append para registrar NOVOS problemas críticos descobertos
- Use core_memory_replace para atualizar o status de problemas existentes
- Use archival_memory_insert para guardar análises detalhadas de código
- Use archival_memory_search quando precisar de contexto de sessões anteriores

PROTOCOLO DE ATUALIZAÇÃO:
Ao final de cada análise, atualize o bloco 'active_issues' com:
[MÓDULO] [SEVERIDADE] [STATUS] Descrição breve do problema

Ao tomar uma decisão importante, atualize 'decisions_log' com:
[DATA-IMPLÍCITA] [AGENTE] Decisão: descrição | Razão: justificativa`;
  }
}
```

## Seção 11 — LangMem: Hot Path + Cold Path (Camada 4)

LangMem (LangChain) é a camada de memória procedural — guarda os "como fazer"
do projeto. Hot Path = memória de acesso imediato na sessão. Cold Path = base
de conhecimento de longo prazo sobre heurísticas e padrões.

```python
# ANTIGRAVITY OMEGA — LangMem Procedural Memory
# Arquivo: /antigravity/memory/procedural_memory.py
# Dependências: pip install langmem langchain-anthropic

from langmem import create_memory_store_manager
from langchain_anthropic import ChatAnthropic
from typing import List, Dict

class AntigravityProceduralMemory:
    """
    Camada de memória procedural — armazena o 'como fazer' do projeto.
    Hot Path: memórias frequentemente acessadas (padrões do projeto)
    Cold Path: base de conhecimento consolidada (heurísticas aprendidas)
    """

    def __init__(self, project_id: str):
        self.project_id = project_id
        self.llm = ChatAnthropic(
            model="claude-sonnet-4-6",
            temperature=0.1
        )
        self.manager = create_memory_store_manager(
            self.llm,
            namespace=(project_id, "procedural"),
            schemas=[
                {
                    "name": "CodePattern",
                    "description": "Padrão de código aprovado para este projeto",
                    "fields": [
                        {"name": "name", "type": "str"},
                        {"name": "pattern", "type": "str"},
                        {"name": "when_to_use", "type": "str"},
                        {"name": "example_code", "type": "str"},
                        {"name": "validated_by", "type": "str"},
                    ]
                },
                {
                    "name": "Heuristic",
                    "description": "Heurística aprendida sobre o projeto ou domínio",
                    "fields": [
                        {"name": "rule", "type": "str"},
                        {"name": "context", "type": "str"},
                        {"name": "source", "type": "str"},
                        {"name": "confidence", "type": "float"},
                    ]
                },
                {
                    "name": "Antipattern",
                    "description": "Antipadrão identificado que deve ser evitado",
                    "fields": [
                        {"name": "name", "type": "str"},
                        {"name": "description", "type": "str"},
                        {"name": "why_bad", "type": "str"},
                        {"name": "better_alternative", "type": "str"},
                    ]
                }
            ]
        )

    async def learn_from_session(self, messages: List[Dict]) -> None:
        """
        Extrai e consolida aprendizados de uma sessão de análise.
        Chamado automaticamente ao final de cada sessão de auditoria.
        """
        await self.manager.ainvoke(
            {"messages": messages},
            config={"configurable": {"namespace": (self.project_id, "procedural")}}
        )

    async def get_relevant_procedures(self, query: str) -> str:
        """
        Recupera procedimentos e heurísticas relevantes para a tarefa atual.
        """
        store = self.manager.store
        results = await store.asearch(
            query=query,
            namespace=(self.project_id, "procedural"),
            limit=10
        )

        if not results:
            return ""

        lines = ["\n## HEURÍSTICAS E PADRÕES PROCEDURAIS APRENDIDOS\n"]
        for item in results:
            value = item.value
            if value.get("type") == "CodePattern":
                lines.append(
                    f"PADRÃO: {value['name']}\n"
                    f"  Quando usar: {value['when_to_use']}\n"
                    f"  Código: {value['example_code'][:200]}..."
                )
            elif value.get("type") == "Heuristic":
                confidence = value.get("confidence", 0)
                lines.append(
                    f"HEURÍSTICA [{confidence:.0%} confiança]: {value['rule']}"
                )
            elif value.get("type") == "Antipattern":
                lines.append(
                    f"EVITAR — {value['name']}: {value['why_bad']}"
                )
        return "\n".join(lines)
```

export async function processarReserva(

## Seção 30 — Action Prioritization Framework

```
ANTIGRAVITY ACTION PRIORITY MATRIX — Baseado em RICE Score Adaptado

FÓRMULA: PRIORITY = (REACH × IMPACT × CONFIDENCE) / EFFORT

Reach (Alcance):
  5 — Afeta todos os usuários ou toda a operação
  3 — Afeta >50% dos usuários ou fluxos principais
  1 — Afeta <20% dos usuários ou fluxos secundários

Impact (Impacto):
  5 — CRÍTICO: perda de dados, brecha de segurança, down do sistema
  4 — ALTO: funcionalidade quebrada para múltiplos usuários
  3 — MÉDIO: funcionalidade degradada, workaround possível
  2 — BAIXO: experiência ruim mas funcional
  1 — MÍNIMO: esteticamente ruim, sem impacto funcional

Confidence (Confiança do diagnóstico):
  Usar o score de confiança da Seção 29 como percentual (0.3 a 0.99)

Effort (Esforço em horas):
  Usar horas estimadas de implementação

CLASSIFICAÇÃO FINAL:
  PRIORITY > 15 → ESTA SEMANA, bloqueia release
  PRIORITY 8-15 → PRÓXIMAS 2 SEMANAS
  PRIORITY 3-7  → PRÓXIMO MÊS
  PRIORITY < 3  → BACKLOG

Exemplo:
  Problema: SQL Injection em busca de reservas
  Reach: 5 (todos usuários) × Impact: 5 (brecha segurança) × Confidence: 0.95
  / Effort: 4 horas = PRIORITY: 5.9 → Mas OVERRIDE para CRÍTICO por natureza
  
  NOTA: Problemas de segurança e corrupção de dados têm OVERRIDE automático
  para ESTA SEMANA, independente do score calculado.
```

## Seção 33 — Arquitetura de Extensão MCP

MCP (Model Context Protocol) é o padrão open-source da Anthropic para
extensibilidade. Permite que os agentes ANTIGRAVITY se conectem a qualquer
ferramenta externa.

```typescript
// ANTIGRAVITY MCP Server — Conecta agentes a ferramentas externas
// Arquivo: /antigravity/mcp/server.ts
// Dependências: npm install @modelcontextprotocol/sdk

import { Server } from "@modelcontextprotocol/sdk/server/index.js";
import { StdioServerTransport } from "@modelcontextprotocol/sdk/server/stdio.js";
import {
  CallToolRequestSchema,
  ListToolsRequestSchema,
} from "@modelcontextprotocol/sdk/types.js";
import { AntigravitySemanticMemory } from "../memory/semantic_memory.js";

const PROJECT_ID = process.env.ANTIGRAVITY_PROJECT_ID || "default";
const memory = new AntigravitySemanticMemory(PROJECT_ID);

const server = new Server(
  { name: "antigravity-mcp", version: "2.0.0" },
  { capabilities: { tools: {} } }
);

// Ferramentas disponíveis via MCP
server.setRequestHandler(ListToolsRequestSchema, async () => ({
  tools: [
    {
      name: "store_architectural_decision",
      description: "Armazena uma decisão arquitetural permanente do projeto",
      inputSchema: {
        type: "object",
        properties: {
          decision: { type: "string", description: "A decisão tomada" },
          rationale: { type: "string", description: "Por que esta decisão" },
          agent: { type: "string", description: "Qual agente tomou a decisão" },
          modules: { type: "array", items: { type: "string" } }
        },
        required: ["decision", "rationale", "agent"]
      }
    },
    {
      name: "retrieve_project_context",
      description: "Recupera contexto relevante do projeto para a tarefa atual",
      inputSchema: {
        type: "object",
        properties: {
          query: { type: "string", description: "O que você está analisando" },
          agent: { type: "string", description: "Qual agente está pedindo" }
        },
        required: ["query", "agent"]
      }
    },
    {
      name: "store_known_issue",
      description: "Registra um problema encontrado no sistema",
      inputSchema: {
        type: "object",
        properties: {
          module: { type: "string" },
          issue: { type: "string" },
          severity: { type: "string", enum: ["crítico", "alto", "médio", "baixo"] },
          status: { type: "string", enum: ["novo", "em-progresso", "resolvido"] },
          agent: { type: "string" }
        },
        required: ["module", "issue", "severity", "status", "agent"]
      }
    },
    {
      name: "get_pending_action_items",
      description: "Recupera action items pendentes de auditorias anteriores",
      inputSchema: {
        type: "object",
        properties: {
          filter_severity: { type: "string" }
        }
      }
    }
  ]
}));

  const { name, arguments: args } = request.params;
  
  switch (name) {
    case "store_architectural_decision": {
      const id = await memory.store_architectural_decision(
        args.decision as string,
        args.rationale as string,
        args.agent as string,
        (args.modules as string[]) || []

      return { content: [{ type: "text", text: `Decisão armazenada: ${id}` }] };
    }
    
    case "retrieve_project_context": {
      const ctx = await memory.retrieve_for_agent(
        args.agent as string,

        args.module as string,
        args.issue as string,

        args.status as string,
        args.agent as string

      return { content: [{ type: "text", text: `Problema registrado: ${id}` }] };
    }
    
    default:

const transport = new StdioServerTransport();

```python
# ANTIGRAVITY OMEGA — Auto-Improvement Engine
# Arquivo: /antigravity/improvement/gap_detector.py
# Executar: mensalmente ou após 50 sessões de auditoria

from dataclasses import dataclass, field
from typing import List, Optional
from enum import Enum
import json
from datetime import datetime

class GapType(Enum):
    COVERAGE = "coverage"        # Domínio não coberto por nenhum agente
    QUALITY  = "quality"         # Agente produzindo outputs abaixo do padrão
    CURRENCY = "currency"        # Conhecimento desatualizado do agente
    CONFLICT = "conflict"        # Dois agentes contradizendo-se sistematicamente

@dataclass
class AgentPerformanceReport:
    agent_name: str
    outputs_analyzed: int
    specificity_score: float      # 1-10: achados têm localização exata?
    completeness_score: float     # 1-10: cobriu todas as dimensões?
    actionability_score: float    # 1-10: soluções são implementáveis?
    accuracy_score: float         # 1-10: diagnósticos eram corretos?
    false_positive_rate: float    # % de problemas apontados que não eram reais
    composite_score: float = field(init=False)
    gaps: List[str] = field(default_factory=list)
    
    def __post_init__(self):
        self.composite_score = (
            self.specificity_score * 0.25 +
            self.completeness_score * 0.25 +
            self.actionability_score * 0.25 +
            self.accuracy_score * 0.20 +
            (1 - self.false_positive_rate) * 10 * 0.05
        )

@dataclass 
class SystemGapReport:
    timestamp: str
    agent_reports: List[AgentPerformanceReport]
    uncovered_domains: List[str]
    proposed_new_agents: List[dict]
    upgrade_recommendations: List[dict]
    system_health: float
    
    def to_markdown(self) -> str:
        lines = [
            "# PROMETHEUS — RELATÓRIO DE AUTO-MELHORIA",
            f"**Data:** {self.timestamp}",
            f"**Saúde Geral do Sistema:** {self.system_health:.1f}/10",
            "",
            "## Scores por Agente",
            "| Agente | Especif. | Complet. | Acionab. | Precisão | SCORE |",
            "|--------|----------|----------|----------|----------|-------|",
        ]
        for r in sorted(self.agent_reports, key=lambda x: x.composite_score):
            flag = "⚠️" if r.composite_score < 7.0 else "✅"
            lines.append(
                f"| {flag} {r.agent_name} | {r.specificity_score:.1f} | "
                f"{r.completeness_score:.1f} | {r.actionability_score:.1f} | "
                f"{r.accuracy_score:.1f} | **{r.composite_score:.1f}** |"
            )
        
        if self.uncovered_domains:
            lines += ["", "## Domínios Sem Cobertura", ""]
            for domain in self.uncovered_domains:
                lines.append(f"- 🔴 {domain}")
        
        if self.upgrade_recommendations:
            lines += ["", "## Upgrades Recomendados", ""]
            for rec in self.upgrade_recommendations:
                lines.append(f"### {rec['agent']}")
                lines.append(f"**Problema:** {rec['issue']}")
                lines.append(f"**Ação:** {rec['action']}")
                lines.append("")
        
        if self.proposed_new_agents:
            lines += ["", "## Novos Agentes Propostos", ""]
            for agent in self.proposed_new_agents:
                lines.append(f"### [{agent['name']}] — {agent['role']}")
                lines.append(f"**Justificativa:** {agent['justification']}")
                lines.append(f"**Gap coberto:** {agent['gap']}")
                lines.append("")
        
        return "\n".join(lines)


class AntigravityGapDetector:
    """
    Analisa a performance do sistema ANTIGRAVITY e propõe melhorias.
    PROMETHEUS usa esta classe para gerar relatórios de auto-melhoria.
    """
    
    PERFORMANCE_THRESHOLD = 7.0  # Score mínimo aceitável para um agente
    
    def analyze_agent_outputs(
        self,
        agent_name: str,
        recent_outputs: List[dict]
    ) -> AgentPerformanceReport:
        """
        Analisa uma amostra de outputs de um agente e gera score.
        Na prática, este método seria alimentado por:
        1. Feedback explícito do usuário (thumbs up/down)
        2. Taxa de reincidência (mesmo problema aparece em próxima auditoria)
        3. Taxa de implementação (action items foram implementados?)
        """
        specificity_scores = []
        completeness_scores = []
        actionability_scores = []
        false_positives = 0
        
        for output in recent_outputs:
            # Métricas de especificidade: tem localização de arquivo/linha?
            has_location = any(
                indicator in output.get("content", "")
                for indicator in [".ts:", ".js:", ".py:", "linha ", "function "]
            )
            specificity_scores.append(9.0 if has_location else 5.0)
            
            # Métricas de completude: tem causa + solução + impacto?
            content = output.get("content", "")
            has_cause = "causa" in content.lower() or "root cause" in content.lower()
            has_solution = "solução" in content.lower() or "código correto" in content.lower()
            has_impact = "impacto" in content.lower() or "negócio" in content.lower()
            completeness_scores.append(
                (has_cause * 3 + has_solution * 4 + has_impact * 3)
            )
            
            # Actionabilidade: tem estimativa de esforço + responsável?
            has_effort = "hora" in content.lower() or "h |" in content
            actionability_scores.append(8.0 if has_effort else 6.0)
            
            # False positives: o usuário marcou como incorreto?
            if output.get("user_feedback") == "incorrect":
                false_positives += 1
        
        n = len(recent_outputs) or 1
        return AgentPerformanceReport(
            agent_name=agent_name,
            outputs_analyzed=n,
            specificity_score=sum(specificity_scores) / n,
            completeness_score=sum(completeness_scores) / n,
            actionability_score=sum(actionability_scores) / n,
            accuracy_score=8.0 - (false_positives / n) * 5,
            false_positive_rate=false_positives / n
        )
    
    def detect_coverage_gaps(
        self,
        recent_user_queries: List[str],
        existing_agents: List[str]
    ) -> List[str]:
        """Detecta domínios nos pedidos dos usuários que nenhum agente cobre."""
        covered_domains = {
            "arquitetura", "segurança", "banco de dados", "api",
            "ia", "prompts", "ux", "produto", "turismo", "operações",
            "financeiro", "contratos", "testes", "qualidade"
        }
        
        uncovered = []
        for query in recent_user_queries:
            query_lower = query.lower()
            if "devops" in query_lower or "ci/cd" in query_lower:
                if "DevOps & CI/CD" not in uncovered:
                    uncovered.append("DevOps & CI/CD")
            if "mobile" in query_lower or "react native" in query_lower:
                if "Mobile Development" not in uncovered:
                    uncovered.append("Mobile Development")
        
        return uncovered
    
    def generate_full_report(
        self,
        agent_outputs: dict,
        recent_queries: List[str]
    ) -> SystemGapReport:
        """Gera o relatório completo de gaps e recomendações."""
        agent_reports = [
            self.analyze_agent_outputs(agent, outputs)
            for agent, outputs in agent_outputs.items()
        ]
        
        system_health = (
            sum(r.composite_score for r in agent_reports) / len(agent_reports)
            if agent_reports else 0
        )
        
        upgrade_recommendations = [
            {
                "agent": r.agent_name,
                "issue": f"Score {r.composite_score:.1f}/10 — abaixo do threshold",
                "action": (
                    f"Revisar checklists de {r.agent_name}. "
                    f"Dimensão mais fraca: "
                    f"{'Especificidade' if r.specificity_score == min(r.specificity_score, r.completeness_score, r.actionability_score) else 'Completude'}"
                )
            }
            for r in agent_reports
            if r.composite_score < self.PERFORMANCE_THRESHOLD
        ]
        
        uncovered = self.detect_coverage_gaps(recent_queries, list(agent_outputs.keys()))
        proposed_new = [
            {
                "name": "DEPLOY",
                "role": "DevOps & CI/CD Engineer",
                "gap": "DevOps & CI/CD",
                "justification": "Múltiplas queries sobre CI/CD detectadas sem agente especializado"
            }
            for domain in uncovered if domain == "DevOps & CI/CD"
        ]
        
        return SystemGapReport(
            timestamp=datetime.now().isoformat(),
            agent_reports=agent_reports,
            uncovered_domains=uncovered,
            proposed_new_agents=proposed_new,
            upgrade_recommendations=upgrade_recommendations,
            system_health=system_health
        )
```

## Seção 37 — Inter-Agent Communication Protocol (IACP)

Protocolo que define como os agentes trocam informações para evitar redundância
e garantir que todos tenham a mesma "consciência" do estado do projeto.

```xml
<iacp_protocol version="omega">
  <rule id="1">
    Nenhum agente começa análise sem carregar o output do agente anterior
    (se houver dependência declarada).
  </rule>
  <rule id="2">
    Agentes devem marcar achados que precisam de validação de outro agente.
    Exemplo: [AXIOM] → [CIPHER]: "Analisei o fluxo de auth, valide a segurança."
  </rule>
  <rule id="3">
    Discordâncias devem ser resolvidas via SEÇÃO 4 (Self-Consistency) 
    em modo colaborativo, buscando evidência nova.
  </rule>
</iacp_protocol>
```

## Seção 39 — Protocolo de Auditoria Profunda (9 Fases)

Este é o processo mais rigoroso do ANTIGRAVITY OMEGA, usado em MIRROR:FULL.

```
FASE 1 — SCOUTING (CHRONOS + ATLAS)
  Carregar memória, histórico e entender contexto de negócio.

FASE 2 — EXPLORATION (AXIOM + VECTOR + PULSE)
  Mapear arquitetura, banco e integrações.

FASE 3 — OFFENSIVE (CIPHER)
  Pentest agressivo e busca de vulnerabilidades.

FASE 4 — OPERATIONAL (ATLAS + ORBIT + LEDGER)
  Testar fluxos de turismo, grupos e contratos financeiros.

FASE 5 — EXPERIENCE (PRISM + DELTA)
  Auditar UX, UI, acessibilidade e valor do produto.

FASE 6 — QUALITY (FORGE)
  Auditar cobertura de testes e injetar falhas (chaos).

FASE 7 — AI AUDIT (NEXUS + ECHO)
  Auditar implementação de IA, prompts e custos.

FASE 8 — SYNTHESIS (MIRROR)
  Consolidar todos os achados em relatório único.

FASE 9 — MEMORY & EVOLVE (PROMETHEUS + CHRONOS)
  Armazenar aprendizados e evoluir o squad.
```
